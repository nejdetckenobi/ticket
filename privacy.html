Privacy Policy

Effective date: August 8, 2026

TicketToken (the “Application”) creates and validates invitation QR codes. This Privacy Policy explains what information the Application processes, why it is processed, where it is stored, and the choices available to users.

Information processed by the Application

The Application may process the following information:

  • Event and invitation information, including an event name, an invitee’s full name, and a cryptographic invitation token.
  • Validation records, including the event name, invitee’s full name, validation timestamp, and invitation token.
  • Application settings, including the shared validation key, validation cooldown, duplicate-prevention preference, storage preference, dark-mode preference, and the identifier and name of a selected Google spreadsheet.
  • Camera frames used to detect QR codes. Frames are processed locally in the browser and are not uploaded or retained by the Application.
  • Optional artwork selected by the user to be blended into generated QR images. The image is resized and stored locally on the user’s device.

How information is used

Information is used only to:

  • Create signed invitation QR codes.
  • Blend user-selected artwork into generated QR images.
  • Verify that scanned invitations have a valid signature.
  • Display and export validation history on the user’s device.
  • Prevent duplicate validation when that option is enabled.
  • Append successful validation records to a Google spreadsheet selected by the user when Google storage is enabled.

Local storage

By default, settings, the normalized optional logo, and validation history are stored in the browser’s local storage on the user’s device. The Application does not operate its own server-side database. Local information remains until the user clears settings or history in the Application, clears browser storage, or removes the Application’s site data.

Logo decoding, resizing, format conversion, and placement are performed entirely in the user’s browser using local browser image and canvas APIs. The logo is not uploaded to the Developer or to a third-party image processing service.

Google Drive and Google Sheets access

Google integration is optional. When a user chooses Google storage, the Application requests permission through Google OAuth and displays Google Picker. The Application uses the https://www.googleapis.com/auth/drive.file scope, which limits access to files the user opens or selects for use with the Application.

The Application accesses only the Google Sheets file selected by the user. It reads the selected spreadsheet’s worksheet metadata and header row and validation records. It writes the event name, invitee’s full name, validation time, and cryptographic invitation token to the first worksheet. When Google storage and duplicate prevention are enabled, it reads existing validation rows from that worksheet to determine whether the invitation token was already validated. The Application does not sell Google user data, use it for advertising, or transfer it to unrelated third parties.

Google OAuth access tokens are held only in browser memory and are not stored in local storage or by an Application backend. The selected spreadsheet’s identifier and name are stored locally so the Application can display the selection on the user’s device. Users must reconnect to Google after the page is reloaded before new records can be written.

The Application’s use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy , including the Limited Use requirements.

Sharing and service providers

The Application does not sell personal information. Information is sent to Google only when the user enables Google storage and authorizes a selected spreadsheet. The Application is hosted by Netlify and loads browser libraries from jsDelivr and Google. Those providers may process standard technical request information, such as IP addresses, user-agent details, and request timestamps, under their own privacy policies.

QR images and their contents may be shared by the user using the device’s share or download features. Any subsequent handling of a shared QR code is controlled by the sender and recipient, not by the Application.

Retention and deletion

  • Use Clear in Settings to remove locally saved settings and the selected spreadsheet reference.
  • Use Clear history to remove local validation records.
  • Delete rows directly in Google Sheets to remove records written to the selected spreadsheet.
  • Revoke the Application’s Google access from the Google Account connections page .

Security and user responsibilities

The Application uses a shared cryptographic key supplied by the user to sign and validate invitations. Users and event organizers are responsible for protecting that key, controlling access to their devices and Google spreadsheets, and ensuring that they have an appropriate basis for processing invitees’ personal information. No method of storage or transmission can be guaranteed to be completely secure.

Children’s privacy

The Application is not directed to children and does not knowingly collect children’s personal information through an operator-controlled service. Event organizers are responsible for obtaining any consent required before entering or processing information about minors.

Changes to this policy

This policy may be updated when the Application’s features or data practices change. The effective date at the top of this page will be updated when changes are published.

Contact

For privacy questions or requests, contact the project maintainer through the TicketToken GitHub issue tracker .
